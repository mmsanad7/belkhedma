# 0010: نستخدم المكوّنات الموجودة الأول، والجديد يتبني بالـ Atomic Design

| البند | القيمة |
|---|---|
| الحالة | معتمد |
| التاريخ | 2026-11-23 |
| صاحب القرار | م. سند (صاحب المشروع) |

## السياق
كل ما بنضيف حاجة جديدة في Figma، ممكن نعمل عناصر مكررة أو frames مرسومة باليد بدل ما نستخدم المكتبة. وده بيكسر ثبات النظام. حصل ده فعلاً في كيان العاملة واتصلّح بعدها (شوف الـ changelog بتاريخ 2026-11-23: `worker_info_chip` اتمسح ومكانه `contract_information_chip`).

## القرار
أي حاجة جديدة بتتبني (شاشة، bottom sheet، مكوّن) بتمشي بالترتيب ده:

1. **دوّر الأول في المكتبة:** صفحات `atoms` و`molecules` و`organisms` و`templates` و`icons`. لو فيه مكوّن يأدي الغرض، استخدمه كـ instance (بـ variant أو property أو slot)، حتى لو محتاج override بسيط في النص.
2. **لو مفيش، اعمل جديد بمبادئ Atomic Design:**
   - المستوى الصح: atom ← molecule ← organism ← template ← screen، والمكوّن الجديد يتبني من instances المستوى اللي تحته.
   - يتحط في صفحته (`atoms` / `molecules` / `organisms` / `icons`).
   - component set بـ `state=default` على الأقل، وخصائص بـ `state=` و`type=` و`status=` و`size=` وقيم `snake_case`.
   - متغيرات بس للألوان والمسافات والـ radius والخطوط. ممنوع القيم الثابتة.
3. **وثّق** المكوّن الجديد في `design-system/` والـ changelog، وقول ليه الموجود ماكانش ينفع.

## المراجعة
أي مراجعة لازم تتأكد إن مفيش frame مرسوم باليد مكان مكوّن موجود، ومفيش مكوّن جديد بيكرر واحد موجود.
